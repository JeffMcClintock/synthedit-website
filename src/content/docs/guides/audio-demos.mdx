Screenshots can show you what a patch looks like. These demos let you hear what the DSP actually does.

Each one isolates a single module, renders it straight out of SynthEdit to disk, and pairs it with a note on the engineering behind what you're hearing. Every clip is served losslessly (FLAC, with an MP3 fallback) — a demo about fidelity shouldn't be judged through a lossy codec.

## Oscillator HD — waveform purity

  <div class="se-demo-grid">
    <img class="se-demo-shot" src="../../images/modules/osc-hd.png" alt="Oscillator HD module showing Pitch, Pulse Width, Waveform, Sync, Phase Mod, Disable and Reset Mode inputs with an Audio Out pin" />
    <div>
      <div class="se-demo-eyebrow">— Demo 01 / Waveform</div>
      <h3 class="se-demo-title">Oscillator HD</h3>
      <p class="se-demo-body">A sawtooth is the hardest waveform to synthesise cleanly: it contains every harmonic, not just the odd ones, so its upper partials pile up against the Nyquist limit. A naive digital oscillator folds those partials back down the spectrum as inharmonic tones that drift <em>against</em> the note instead of tracking it — the metallic, faintly detuned grit that gives cheap soft synths away. Oscillator HD generates band-limited waveforms so the harmonic series stays intact all the way up.</p>

  <p class="se-demo-listen"><strong>What to listen for:</strong> the demo alternates deep bass notes with mid-register chords. The sustained low notes are the real test — a sawtooth down there packs hundreds of harmonics into the top of the audible band. Listen behind the note for any metallic shimmer that fails to move with the pitch. It should stay clean and stable, the brightness simply thinning out as the harmonics run out of room.</p>

The pitch, pulse width, sync and phase-modulation inputs are all audio-rate, so the oscillator can be driven as fast as the signal feeding it — which is what makes it usable as an FM operator as well as a voice.

## StateVar Filter — audio-rate modulation

<div class="se-demo">
  <div class="se-demo-grid">
    <img class="se-demo-shot" src="../../images/modules/statevar-filter.png" alt="StateVar Filter module showing Signal, Pitch, Resonance, Strength and Mode inputs with an Output pin" />
    <div>
      <div class="se-demo-eyebrow">— Demo 02 / Filters / VA</div>
      <h3 class="se-demo-title">StateVar Filter (TPT)</h3>
      <p class="se-demo-body">This demo runs the filter where it is least forgiving: two-stage, resonance well up, with an envelope sweeping the cutoff on every note and the cutoff tracking the keyboard as well. High resonance acts as a magnifying glass on the cutoff parameter itself — if the frequency were only recalculated once per processing block, each step would ring the resonant peak and you would hear it as zipper noise or a gritty stair-step in the sweep. The StateVar Filter's Pitch and Resonance are both audio-rate inputs, recalculated every sample, and its topology-preserving transform (TPT) design keeps the filter stable and its tuning accurate while those values move.</p>
    </div>
  </div>

  <p class="se-demo-listen"><strong>What to listen for:</strong> the resonant peak sweeping through each note. It should glide continuously, with no stepping, buzzing or granularity riding on top of the sweep — and the resonance should stay musical rather than spitting at the extremes.</p>

Because cutoff is an ordinary audio-rate pin, nothing stops you patching an oscillator into it rather than an envelope — the filter will track it at full rate.

See the [StateVar Filter reference](../../reference/filters/statevar-filter/) for modes and parameters.

## Wavetable Osc — morphing the table

<div class="se-demo">
  <div class="se-demo-grid se-demo-grid-wide">
    <img class="se-demo-shot se-demo-shot-display" src="../../images/modules/wavetable-osc.png" alt="Wavetable Osc display showing a stack of single-cycle waveforms, with the currently selected slot highlighted in yellow" />
    <div>
      <div class="se-demo-eyebrow">— Demo 03 / Waveform / Wavetable</div>
      <h3 class="se-demo-title">Wavetable Osc</h3>
      <p class="se-demo-body">A wavetable oscillator stores a stack of single-cycle waveforms in one file and plays back a position within that stack — the yellow trace in the display is the slot currently sounding. Two things make this awkward to do well. Each slot is a fixed-length cycle being replayed at whatever pitch you ask for, so its stored harmonics transpose along with it and the bright end of the table is where aliasing shows up first. And the position is itself a moving target: jump between neighbouring waves and the discontinuity arrives as a click, or as a stepped grind riding on top of the note. Wavetable Osc takes both <strong>Pitch</strong> and <strong>Slot</strong> as audio-rate inputs, so the position is resolved every sample rather than once per processing block. In this demo the ADSR is patched straight into Slot, so every note travels the depth of the table as it sounds.</p>
    </div>
  </div>
  <audio controls preload="none">
    <source src="../../audio/wavetable-osc-demo.flac" type="audio/flac" />
    <source src="../../audio/wavetable-osc-demo.mp3" type="audio/mpeg" />

  </audio>
  <p class="se-demo-listen"><strong>What to listen for:</strong> the timbre morphing continuously as the envelope walks each chord through the table. The movement should be smooth — no clicks where the slot boundaries fall, no stepping or zipper noise riding on the sweep — and the bright end of the table should thin out cleanly rather than breaking into inharmonic fizz. The chords are deliberately unstable and slow, which gives the table time to travel and leaves the morph exposed.</p>
  <div class="se-demo-facts">
    <span>48 kHz · 16-bit stereo</span>

Because Slot is an ordinary audio-rate pin, an LFO — or another oscillator — can drive it as readily as an envelope. The table itself is just a `.wav`; this one is assembled from single-cycle waves out of the free Adventure Kid (AKWF) library.

## Building these yourself

All three demos were rendered from ordinary SynthEdit projects using the **Wave Recorder** module, which writes the output straight to a `.wav` file — no external recorder or DAW involved. The [Rendering to Disk guide](../rendering-to-disk/) walks through the process.
